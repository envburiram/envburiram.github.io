# ระบบรับสมัครสมาชิก ชมรมอนามัยสิ่งแวดล้อมจังหวัดบุรีรัมย์

ระบบทะเบียนสมาชิกที่ทำงานทั้งหมดบน Google Apps Script + Google Sheets
ไม่ต้องเช่าเซิร์ฟเวอร์ ไม่มีค่าใช้จ่ายรายเดือน

| ความสามารถ | รายละเอียด |
|---|---|
| รับสมัครออนไลน์ | ฟอร์มสาธารณะ ตรวจเลขบัตรประชาชน 13 หลัก อัปโหลดรูป เซ็นชื่อบนจอได้ ได้เลขที่ใบสมัคร `APP-2569-0001` |
| เลขสมาชิก | ออกเมื่ออนุมัติ รูปแบบ `MEM-2569-0001` (แบบเดียวกับระบบ envbrclub-supabase) ลำดับไม่ซ้ำแม้ลบข้อมูล |
| ล็อกอินผู้ดูแล | 3 ระดับสิทธิ์ ล็อกบัญชีเมื่อเดารหัสผ่าน บังคับเปลี่ยนรหัสครั้งแรก |
| แก้ไขข้อมูล | แก้ได้ทุกฟิลด์ รวมรูปถ่ายและลายเซ็น ต้องระบุเหตุผลทุกครั้ง |
| ต่ออายุ / ออกบัตรใหม่ | ต่ออายุตามอายุบัตรในค่าตั้งค่า (เริ่มต้น 1 ปี) ออกบัตรใบใหม่แล้ว QR ใบเดิมใช้ไม่ได้ |
| ประวัติการแก้ไข | บันทึกว่าใคร แก้ฟิลด์ไหน จากค่าอะไรเป็นอะไร เมื่อไร |
| ส่งออก | Excel (.xlsx) และ CSV มี BOM ภาษาไทยไม่เพี้ยน |
| บัตรสมาชิก | ขนาดจริง CR80 (85.6 × 53.98 มม.) พิมพ์หรือบันทึกเป็น PDF |
| QR ตรวจสอบ | อยู่หลังบัตร สแกนแล้วเห็นสถานะสมาชิกทันที |
| เข้ารหัส | ข้อมูลส่วนบุคคลเข้ารหัสรายฟิลด์ก่อนลงชีต กุญแจเก็บแยก |
| เอกสารกฎหมาย | ประกาศความเป็นส่วนตัวในระบบ + ชุดเอกสาร PDPA ใน `LEGAL.md` |

## 1. ติดตั้ง (ครั้งเดียว ประมาณ 15 นาที)

**1.1 สร้างโปรเจกต์**
ไปที่ https://script.google.com → New project → ตั้งชื่อ `ระบบสมาชิกชมรมอนามัยสิ่งแวดล้อมจังหวัดบุรีรัมย์`

**1.2 ใส่ไฟล์**
สร้างไฟล์ตามรายการนี้ให้ชื่อตรงกันทุกตัวอักษร (ชื่อไฟล์คือสิ่งที่โค้ดใช้เรียกหากัน)

| ในโปรเจกต์ | ชนิด | จากไฟล์ |
|---|---|---|
| `Code` | สคริปต์ | Code.gs |
| `Crypto` | สคริปต์ | Crypto.gs |
| `Auth` | สคริปต์ | Auth.gs |
| `Members` | สคริปต์ | Members.gs |
| `Audit` | สคริปต์ | Audit.gs |
| `Export` | สคริปต์ | Export.gs |
| `Shared` | HTML | Shared.html |
| `Register` | HTML | Register.html |
| `Admin` | HTML | Admin.html |

| `Privacy` | HTML | Privacy.html |
| `QRLib` | HTML | QRLib.html (ไลบรารีสร้าง QR หลังบัตร) |

จากนั้นเปิด ⚙️ Project Settings → ติ๊ก *Show "appsscript.json" manifest file* แล้ววางเนื้อหาจาก `appsscript.json` ทับของเดิม

**1.3 สร้างฐานข้อมูล**
เลือกฟังก์ชัน `setup` แล้วกด Run → กด Review permissions → เลือกบัญชี → Advanced → Go to project (unsafe) → Allow

ดูผลลัพธ์ที่หน้าต่าง Execution log จะได้ **ชื่อผู้ใช้และรหัสผ่านผู้ดูแลชุดแรก — จดไว้ทันที** (แสดงครั้งเดียว)

หากขึ้นข้อความสีแดงแทน ให้กด Run ซ้ำอีกครั้ง แล้วรันฟังก์ชัน `diagnose` เพื่อตรวจว่าทุกตารางถูกต้อง

**1.4 เผยแพร่เว็บ**
Deploy → New deployment → เลือก Web app
- Execute as : **Me**
- Who has access : **Anyone**

คัดลอก URL ที่ได้ แล้วกลับไปที่ Project Settings → Script Properties → Add property
`WEBAPP_URL` = URL ที่คัดลอกมา (สำคัญมาก เพราะ QR หลังบัตรใช้ค่านี้)

**1.5 ตั้งค่าชมรม**
เปิด `URL?page=admin` → เข้าสู่ระบบ → เปลี่ยนรหัสผ่าน → แท็บ *ตั้งค่าชมรม*
แก้ชื่อชมรม ที่อยู่ ชื่อประธาน ให้ตรงกับความจริง

**1.6 ตราชมรมและลายเซ็นประธาน (ถ้ามี)**
อัปโหลดไฟล์ PNG พื้นหลังโปร่งขึ้น Google Drive → คลิกขวา → Share → คัดลอกลิงก์
รหัสไฟล์คือส่วน `/d/XXXXX/` ในลิงก์ นำ `XXXXX` ไปใส่ช่อง *รหัสไฟล์ตราชมรม* และ *รหัสไฟล์ลายเซ็นประธาน*
(ไฟล์ต้องอยู่ในบัญชีเดียวกับที่ deploy ระบบ)

**1.7 อัปเดตจากรุ่น 1.0.0 (ระบบที่ติดตั้งไว้แล้ว)**
หลังวางโค้ดใหม่ ให้รัน `diagnose()` หนึ่งครั้ง ระบบจะเพิ่มหัวคอลัมน์ `app_no` (เลขที่ใบสมัคร) ต่อท้ายตาราง `Members`
โดยไม่แตะข้อมูลเดิม จากนั้นเปิดแท็บ *ตั้งค่าชมรม* ตรวจข้อมูลชมรม และค่าใหม่ *อายุบัตรสมาชิก* (เริ่มต้น 1 ปี)
- ค่าที่เคยบันทึกในตาราง `Settings` ยังใช้ค่าเดิม ค่าเริ่มต้นชุดใหม่ (ที่อยู่ โทรศัพท์ อีเมล ชื่อประธาน) มีผลเฉพาะช่องที่ว่าง
- เลขสมาชิกเดิมรูปแบบ `BR-69-0001` ใช้ได้ตามเดิม สมาชิกที่อนุมัติหลังอัปเดตได้เลขรูปแบบ `MEM-2569-0001`
- ประกาศความเป็นส่วนตัวเปลี่ยนเป็นฉบับ 2569.2 (ระยะเก็บรักษา 5 ปี) ผู้สมัครใหม่ให้ความยินยอมตามฉบับนี้

## 3. งานประจำของผู้ดูแล

**อนุมัติผู้สมัคร** ทะเบียนสมาชิก → เลือกคนที่สถานะ *รอตรวจสอบ* (คอลัมน์แรกแสดงเลขที่ใบสมัคร) → แก้ไข
→ เปลี่ยนสถานะเป็น *สมาชิกปัจจุบัน* → กรอก *เหตุผลในการแก้ไข* (เช่น "อนุมัติใบสมัคร") → บันทึก
ระบบจะออกเลขสมาชิก `MEM-<ปี พ.ศ.>-<ลำดับ>` วันออกบัตร และวันหมดอายุตามค่าตั้งค่า *อายุบัตรสมาชิก* (เริ่มต้น 1 ปี) ให้อัตโนมัติ
ทุกการแก้ไขต้องระบุเหตุผล ระบบบันทึกเหตุผลไว้ในประวัติพร้อมรายการที่เปลี่ยน

**ไม่อนุมัติผู้สมัคร** ผู้ดูแลระดับสูงสุดกด *ลบข้อมูลสมาชิก* ระบุเหตุผล แล้วพิมพ์ชื่อ-นามสกุลยืนยัน (ดูหัวข้อการลบด้านล่าง)

**ต่ออายุสมาชิก** เปิดสมาชิก → ปุ่ม *ต่ออายุสมาชิก* → ระบุเหตุผล/หลักฐาน
ถ้าบัตรยังไม่หมดอายุ ช่วงใหม่ต่อจากวันหมดอายุเดิม ถ้าหมดอายุแล้วเริ่มนับวันนี้ (กติกาเดียวกับระบบ envbrclub-supabase) แล้วพิมพ์บัตรใบใหม่

**บัตรหาย / ข้อมูลบนบัตรเปลี่ยน** ปุ่ม *ออกบัตรใบใหม่* → ระบุเหตุผล → ระบบเปลี่ยนรหัส QR ทันที
บัตรใบเดิมสแกนแล้วจะไม่พบในระบบ จากนั้นกด *พิมพ์บัตรสมาชิก*

**ยุติสมาชิกภาพ** แก้ไขสถานะเป็น *พ้นสมาชิกภาพ* พร้อมเหตุผล (ไม่ใช้การลบ เพื่อคงประวัติไว้ตรวจสอบได้)

**ลบข้อมูลสมาชิก** (เฉพาะ superadmin) ปุ่ม *ลบข้อมูลสมาชิก* → ระบุเหตุผล → พิมพ์ชื่อ-นามสกุลให้ตรง
- ลบถาวรทั้งทะเบียน รูปถ่าย และลายเซ็น ส่วนบันทึกความยินยอมและประวัติการใช้งานยังคงอยู่เป็นหลักฐาน
- ผู้ที่เคยได้รับบัตรสมาชิกแล้ว **ลบไม่ได้** จนกว่าจะพ้นสมาชิกภาพหรือหมดอายุมาแล้วเกินระยะเก็บรักษา 5 ปี
- คำขอลบตามมาตรา 33 ของสมาชิกที่เคยได้รับบัตร ให้เจ้าของระบบใช้ฟังก์ชัน `eraseMemberOnRequest()` (หัวข้อ 5)

**พิมพ์บัตร** เปิดสมาชิกที่อนุมัติแล้ว → ปุ่ม *พิมพ์บัตรสมาชิก* → เปิดแท็บใหม่ → กด *พิมพ์ / บันทึกเป็น PDF*
- ในกล่องพิมพ์เลือก Destination = **Save as PDF**, Margins = **None**, ปิด *Headers and footers*, เปิด *Background graphics*
- จะได้ไฟล์ 2 หน้า (หน้า–หลัง) ขนาดเท่าบัตรจริง ส่งร้านพิมพ์ได้เลย
- ถ้าจะพิมพ์เองบนกระดาษ A4 ให้ติ๊ก *พิมพ์ลงกระดาษ A4* ก่อนกดพิมพ์
- ลิงก์พิมพ์บัตรมีอายุ 10 นาที และถูกบันทึกลงประวัติทุกครั้ง

**ส่งออกข้อมูล** แท็บ *ส่งออกข้อมูล* → เลือกชุดข้อมูลและเงื่อนไข → ดาวน์โหลด
โดยปกติเลขบัตรประชาชนจะถูกปกปิด เฉพาะ superadmin เท่านั้นที่ติ๊กขอไฟล์แบบเต็มได้ และจะถูกบันทึกไว้ว่าใครขอเมื่อไร

## 4. ระดับสิทธิ์

| สิทธิ์ | ทำอะไรได้ |
|---|---|
| `superadmin` | ทุกอย่าง + จัดการบัญชีผู้ดูแล + ตั้งค่า + เห็นเลขบัตรประชาชนเต็ม + ลบข้อมูลสมาชิก |

| `viewer` | ดูรายชื่อและประวัติเท่านั้น แก้ไขและส่งออกไม่ได้ |

## 5. ฟังก์ชันสำหรับผู้ดูแลระบบ (รันจากตัวแก้ไขสคริปต์)

ฟังก์ชันเหล่านี้รันได้จากตัวแก้ไขสคริปต์โดยบัญชีเจ้าของระบบเท่านั้น ถ้าถูกเรียกจากหน้าเว็บจะถูกปฏิเสธ
(ระบบจึงขอสิทธิ์อ่านอีเมลของบัญชีที่รัน — scope `userinfo.email`) รหัสผ่านที่สร้างใหม่แสดงเฉพาะใน Execution log

| ฟังก์ชัน | ใช้เมื่อ |
|---|---|
| `setup()` | ติดตั้งครั้งแรก หรือเรียกซ้ำเพื่อซ่อมตารางที่หายไป (ไม่ลบข้อมูลเดิม) |
| `diagnose()` | **ตรวจสุขภาพระบบและซ่อมโครงสร้างตารางอัตโนมัติ** ใช้เมื่อหน้าเว็บแจ้งข้อผิดพลาด |
| `selfTestCrypto()` | ตรวจว่าระบบเข้ารหัสทำงานปกติ |
| `resetSuperadminPassword()` | ลืมรหัสผ่านผู้ดูแลสูงสุด |
| `rotateEncryptionKey()` | สงสัยว่ากุญแจรั่ว — **สำรองสเปรดชีตก่อนเสมอ** (เข้ารหัสใหม่ทั้งทะเบียนสมาชิกและรายละเอียดใน AuditLog ถ้าหยุดกลางทางให้รันซ้ำ ระบบจะทำต่อด้วยกุญแจชุดเดิม) |
| `dailyMaintenance()` | ปรับสถานะบัตรหมดอายุ ล้างเซสชัน (ตั้งเวลาอัตโนมัติไว้แล้วทุกวัน 03:00 น.) |
| `eraseMemberOnRequest()` | ลบข้อมูลตามคำขอมาตรา 33 ของผู้ที่เคยได้รับบัตร (หน้าเว็บไม่อนุญาต) : ตั้ง Script Property `ERASE_REQUEST` = `เลขสมาชิกหรือเลขที่ใบสมัคร \| เหตุผล` แล้วกด Run |

## 6. การสำรองข้อมูล

- **สเปรดชีต** File → Make a copy ทุกเดือน หรือเปิด Version history ไว้
- **กุญแจเข้ารหัส** คัดลอกค่า `MASTER_KEY_B64` (และ `MASTER_KEY_PREV_B64` / `MASTER_KEY_NEXT_B64` ถ้ามี) จาก Script Properties เก็บในที่ปลอดภัยแยกจากสเปรดชีต

> **สำคัญ** สำเนาสเปรดชีตอย่างเดียวกู้ข้อมูลไม่ได้ ต้องมีกุญแจด้วย
> และในทางกลับกัน คนที่ได้สเปรดชีตไปโดยไม่มีกุญแจก็อ่านข้อมูลส่วนบุคคลไม่ได้ — นี่คือเจตนาของการออกแบบ

## 7. ข้อจำกัดที่ควรทราบ

- เหมาะกับสมาชิกระดับไม่เกินประมาณ 3,000 คน มากกว่านี้หน้าทะเบียนจะเริ่มช้าเพราะต้องถอดรหัสทั้งตาราง
- การเข้าสู่ระบบใช้เวลาราว 2–5 วินาที เพราะคำนวณรหัสผ่านแบบ PBKDF2 12,000 รอบโดยตั้งใจให้ช้า
  (ปรับได้ที่ `CRYPTO_CFG.PBKDF2_ITER` ใน `Crypto.gs` — ลดแล้วเร็วขึ้นแต่ปลอดภัยน้อยลง)
- Apps Script จำกัดเวลาทำงาน 6 นาทีต่อครั้ง และ URL Fetch 20,000 ครั้ง/วัน ซึ่งเพียงพอสำหรับงานชมรม
- ไลบรารีสร้าง QR หลังบัตรฝังอยู่ในระบบ (`QRLib.html`) ไม่โหลดจาก CDN และไม่ส่ง URL ตรวจสอบบัตรให้บริการภายนอก
- Apps Script ไม่สามารถอ่านหมายเลข IP ของผู้ใช้ได้ ประวัติจึงบันทึกเป็นข้อมูลเบราว์เซอร์แทน

**เปิดหน้าผู้ดูแลแล้วไม่มีรายชื่อสมาชิก / กดบันทึกแล้วขึ้น error**

เปิดตัวแก้ไขสคริปต์ → เลือกฟังก์ชัน `diagnose` → Run → อ่านผลใน Execution log
ฟังก์ชันนี้จะตรวจทุกตาราง ซ่อมโครงสร้างที่ผิดให้อัตโนมัติโดยไม่แตะข้อมูลเดิม แล้วรีเฟรชหน้าเว็บอีกครั้ง

สาเหตุที่พบบ่อยคือ `setup()` รอบแรกทำงานไม่จบ ทำให้ตาราง `Members` ไม่มีหัวคอลัมน์
(ชีตที่ Google สร้างใหม่มี 26 คอลัมน์ แต่ตารางนี้ต้องใช้ 36 คอลัมน์)

**สแกน QR แล้วเปิดไม่ได้ / ลิงก์ผิด**
ยังไม่ได้ตั้ง Script Property ชื่อ `WEBAPP_URL` หรือตั้งเป็น URL ของ deployment เก่า
ตั้งใหม่แล้วต้องพิมพ์บัตรใหม่ เพราะ QR ที่พิมพ์ไปแล้วฝัง URL เดิมไว้

**กดพิมพ์บัตรแล้วไม่มีอะไรเกิดขึ้น**
เบราว์เซอร์บล็อกหน้าต่างใหม่ — กดอนุญาต pop-up ของโดเมน `script.google.com` แล้วลองอีกครั้ง

**ขึ้นข้อความ `[ข้อมูลถูกแก้ไข]` ในช่องข้อมูล**
มีคนแก้ค่าที่ขึ้นต้นด้วย `v1:` ในสเปรดชีตด้วยมือ ให้กู้จาก Version history ของสเปรดชีต

**เข้าสู่ระบบไม่ได้ทุกบัญชี**
เรียก `resetSuperadminPassword()` จากตัวแก้ไขสคริปต์เพื่อขอรหัสผ่านใหม่

**หน้าเว็บขึ้นว่าเซสชันหมดอายุบ่อย**
ปกติเซสชันมีอายุ 6 ชั่วโมง เซสชันจะถูกยกเลิกทันทีเมื่อบัญชีถูกระงับ เปลี่ยนสิทธิ์ ถูกตั้งรหัสผ่านใหม่
หรือเจ้าของบัญชีเปลี่ยนรหัสผ่านจากอุปกรณ์อื่น ให้เข้าสู่ระบบใหม่

**เข้าสู่ระบบแล้วเห็นแต่หน้าต่างเปลี่ยนรหัสผ่าน**
บัญชีใหม่หรือบัญชีที่ถูกตั้งรหัสผ่านใหม่ต้องเปลี่ยนรหัสผ่านก่อน ระบบปฏิเสธคำขออื่นทั้งหมดจนกว่าจะเปลี่ยน

**ขึ้นข้อความ "ไม่พบกุญแจเข้ารหัส (MASTER_KEY_B64)"**
Script Property `MASTER_KEY_B64` หายไป ระบบจะหยุดทำงานแทนการสร้างกุญแจใหม่ (ซึ่งจะทำให้ข้อมูลเดิมอ่านไม่ได้)
ให้นำค่าที่สำรองไว้ตามหัวข้อ 6 กลับมาใส่ใน Script Properties

## 9. โครงสร้างฐานข้อมูล

| ตาราง | เก็บอะไร |
|---|---|
| `Members` | ทะเบียนสมาชิก (ฟิลด์ส่วนบุคคลเข้ารหัส + ดัชนีค้นหาแบบ HMAC) |
| `Admins` | บัญชีผู้ดูแล (รหัสผ่านเป็น PBKDF2 hash + salt) |
| `AuditLog` | ประวัติทุกเหตุการณ์ รายละเอียดการแก้ไขเข้ารหัสไว้ |
| `Sessions` | เซสชันที่ยังไม่หมดอายุ (เก็บเฉพาะค่าแฮชของโทเคน) |
| `ConsentLog` | หลักฐานการให้ความยินยอมตาม PDPA |
| `Settings` | ค่าตั้งต้นของชมรมที่แสดงบนบัตรและหน้าเว็บ |

ห้ามแก้ไขค่าในตารางเหล่านี้ด้วยมือ โดยเฉพาะช่องที่ขึ้นต้นด้วย `v1:`
ถ้าแก้ ระบบจะตรวจพบและแสดงว่า `[ข้อมูลถูกแก้ไข]`
